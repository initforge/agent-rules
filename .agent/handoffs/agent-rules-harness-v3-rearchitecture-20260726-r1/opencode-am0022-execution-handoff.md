## Mandatory execution invariants

- Before fan-out, inspect active processes/sessions/branches/worktrees and freeze the real tracked/index/untracked dirty candidate into one immutable epoch. Never branch from stale `HEAD`.
- The main coordinator is outside the child count and consumes only bounded, evidence-addressed receipts. Normal is 8 children (`4 writer + 2 verifier + 1 reviewer + 1 integration`); safe burst is 10 (`5 + 2 + 2 + 1`). Keep at least 6 while independent READY work exists; a lower count requires observed evidence and immediate refill when the constraint clears.
- Every writer has an isolated worktree, immutable base, exclusive path and semantic leases, acceptance criteria, rollback, and no shared mutation surface. Only candidate-bound reviewed snapshots enter the rolling local integration train; any relevant post-review change stales its proof and review.
- Verification is claim-matched and rolling: deterministic T0 proof, independent T1 review, specialist/adversarial T2/T3 review, then complete terminal architecture/security/maintainability/full-stack/UX/install/release convergence as applicable.
- Semantic progress means accepted diff/evidence/checkpoint movement, not logs or heartbeats. On no progress, checkpoint and diagnose the affected child, terminate/reassign only its owned process group, preserve useful partial evidence, and change writer/task shape/design/review tier on the third equivalent failure. Never stall independent siblings.
- Anti-stall guarantees bounded recovery, not impossible failure: every active child/main wait exposes last semantic cursor and deadline; soft stall diagnoses, hard stall checkpoints and cancels/reassigns the exact owned child, repeated equivalent failure changes strategy, and unrelated READY work continues. Queued owner steering must have observable age and an out-of-band delivery/interrupt path instead of waiting forever for a blocked main turn.
- OpenCode stuck-case conformance is mandatory: journal parent/child/task/worktree/lease/process identity before awaiting; reconcile child terminal state independently of the parent spinner or event stream; permit no unresolved `ask`/interactive `question` in autonomous roles; deny child `task` and enforce depth 1 independently of global config; apply finite provider, MCP, tool and semantic-progress deadlines; and exact-reap owned descendants on success, failure, cancel and parent crash. Installed fresh-process fault injection must cover hidden permission waits, recursive dispatch, phantom-running/crashed children, missing child IDs, event/directory mismatch, never-final provider/tool output, hung MCP and Windows process/shim failure.
- `HIGH-ENDURANCE-STEP-BUDGET` triples the current installed role ceilings: coordinator and primary writer `120`; debugger `96`; secondary writer, reviewer, verifier, specialist reviewer, context auditor and integration owner `72`; light/utility worker `48`. Reaching the ceiling with continued semantic progress produces `STEP_LIMIT_CHECKPOINTED`, never PASS or generic failure, and automatically resumes from that checkpoint without owner interaction. A repeated equivalent step-limit must shrink/split the remaining scope or change writer/strategy; it must not discard work, loop the same task, block siblings, or weaken the independent semantic watchdog.
- The installed debug/doctor surface reports canonical versus loaded config generation/hash, role registry and permissions, requested/resolved/observed capability mapping, active child/session state, last semantic progress, queued-message age, owned PID/process groups, ports, test leases/workers, MCP/browser/Compose ownership, and orphan candidates. Target 70–90% lower p50 wall time for parallelizable medium/large work without weakening quality; record p95, retries, merge/review wait, escaped defects, and reasons for running below the declared pool.

Where Vitest is native, cap it at two parent processes per project, one internal worker each with file parallelism off; a full suite atomically owns both slots.
