# Execution, Planning và Bounded Delegation

Ship core outcomes first, bound blockers to release criteria, and terminate when acceptance is proven.
The user-selected model owns the active session phase. Same-session planning and implementation is the default. When the owner explicitly hands a plan to another session or host, the planning model must emit a portable handoff and the receiving user-selected model owns implementation end to end. The harness never selects or switches models, invents worker classes, decomposes work into role theatre, or delegates merely to reduce cost. Delegation is an explicit optimization for genuinely independent work, never the default execution architecture.

Use the host's native plan mode and native progress surface when available. A user-pasted portable plan is authoritative execution input, not a shadow plan or a reason to emulate a missing host surface. Scale planning to the work: a small task needs only outcome, scope and proof; resumable work adds dependencies and a compact checkpoint. Do not create standalone tickets, duplicate task graphs, shadow ledgers, embedded canonical payloads, or per-step status artifacts when the native plan already carries the required state.
Long or portable plans must be cold-start executable from the plan, repository and named accessible resources without conversation history. Include source starting state, scope and non-goals, settled owner decisions, domain-appropriate target locators, dependency order, invariants, acceptance, exact focused proof and stop condition. Materialize task-specific conclusions from skills, images, logs, links and other evidence; never leave orphan pointers such as ordinal attachments or conversational references. Each implementation slice names its target, current-to-expected delta, dependencies, invariants and proof. Agent Rules never persists repository plan history or progress; the native host owns active resume state.
Edit canonical source first and require context evolution audits.

Implement the dependency-ready core slice before broad verification. Each changed seam gets one cheapest-sufficient focused proof plan and, after repair, one focused recheck limited to the failed proof and affected direct dependents.
Do not rerun unchanged proof, full suites, packed dogfood, mutation review, or multi-host conformance outside an explicit material-risk trigger or dependency-defined release gate.
Stop when required acceptance is proven and no material blocker remains. Do not add opportunistic cleanup, polish, ceremony, or scope after that point; perform only lifecycle cleanup already required by the plan.

Subagents default to zero; max two, no recursion, only independent research/review/diagnosis/non-overlapping work explicitly selected by the running model or owner.
A single selected model may plan and implement, or the owner may explicitly hand a portable plan to another selected implementation model. Independent review is required only by a material risk or owner request.

Enforcement: native intake behavior, proof-policy, host-native progress and installer readback.
