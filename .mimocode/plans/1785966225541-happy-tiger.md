## Phase 1: Fix Runner False-PASS Bugs (CRITICAL)

Đây là phần quan trọng nhất. Runner hiện có 4 lỗ hổng false-PASS:

### 1A. Agent exit code check
**Bug:** `allPassed` chỉ check verification exit codes, bỏ qua agent exit code.
**File:** `packages/engine/src/runner/loop.ts`
**Fix:**
```typescript
// After executor.execute()
if (result.exitCode !== 0) {
  // Agent failed — this is NOT a pass, regardless of verification
  outcome = 'failed';
}
```

### 1B. Diff delta trước/sau task
**Bug:** Diff tính `git diff HEAD` sau task, không phải delta trước/sau. Diff cũ cộng dồn.
**File:** `packages/engine/src/runner/diff.ts` + `loop.ts`
**Fix:**
```typescript
// Before task: capture tree SHA
const beforeSha = captureTreeSha(cwd);

// After task: compute delta
const afterSha = captureTreeSha(cwd);
const delta = computeDelta(beforeSha, afterSha, ownedPaths);

// Reject if no real change
if (!delta || delta.linesAdded === 0 && delta.linesDeleted === 0) {
  outcome = 'failed'; // Agent produced no changes
}
```
Thay vì `git diff HEAD`, dùng `git diff <beforeSha> <afterSha>` scoped to ownedPaths.

### 1C. Ownership enforcement
**Bug:** Agent sửa ngoài ownership bị bỏ qua thay vì reject.
**File:** `packages/engine/src/runner/loop.ts`
**Fix:**
```typescript
// After task: check all changed files
const changedFiles = getChangedFiles(beforeSha, afterSha);
const violations = changedFiles.filter(f => !isOwned(f, task.ownedPaths));
if (violations.length > 0) {
  outcome = 'failed'; // Ownership violation
  journal.append({ type: 'OWNERSHIP_VIOLATION', files: violations });
}
```

### 1D. Atomic queue transitions
**Bug:** `recoverAbandoned()` phục hồi mọi file trong active/ mà không check lease/PID.
**File:** `packages/engine/src/runner/queue.ts`
**Fix:**
- Lease file chứa `{ pid, hostname, nonce, claimedAt }`
- `recoverAbandoned()` chỉ recover khi: lease stale (>30 phút) HOẶC PID đã chết
- `settle()` dùng atomic rename: `active/<id>` → `done/<id>` (không delete rồi create)

### 1E. Journal lock recovery
**Bug:** Kill đúng thời điểm có thể khóa journal vĩnh viễn.
**File:** `packages/engine/src/runner/journal.ts`
**Fix:**
- Lock directory chứa `{ pid, timestamp }`
- On startup: nếu lock tồn tại VÀ PID đã chết VÀ timestamp > 5 phút → break lock
- Log warning khi break stale lock

**Verification — 6 Gates bắt buộc:**
```
Gate 1: Agent exit ≠ 0 → outcome = failed (không phải done)
Gate 2: Dirty diff trước task không được tính cho task sau
Gate 3: Edit ngoài ownership → outcome = failed
Gate 4: Hai runners không chạy trùng task (atomic claim)
Gate 5: Kill tại mọi state transition → resume đúng (no data loss, no duplicate)
Gate 6: Journal verify pass sau clean run + after crash recovery
```

Mỗi gate có test riêng. TẤT CẢ phải pass trước khi tiếp tục.

## Orchestration Strategy

### Không cần orchestration phức tạp

**Runner atomic queue đã hỗ trợ parallelism:**
```bash
# Terminal 1
agent-rules runner start --agent claude

# Terminal 2 (parallel, safe — atomic queue)
agent-rules runner start --agent claude
```

**Layered approach, chỉ implement khi cần:**

| Layer | Khi nào | Effort |
|-------|----------|--------|
| 0: Sequential runner | Hiện tại | Done |
| 1: Multi-process runners | Cần parallel tasks | 0 code — chỉ chạy N instances |
| 2: Task→agent routing | Cần different agents per task | ~50 lines — `--agent` flag |
| 3: Dependency scheduler | Cần ordered execution | ~200 lines — thin process trên queue |

**Không cần controller.ts, supervisor.ts, resource-broker.ts.** Queue-based, event-driven, crash-safe.
